# Coverage Climber

vitest v8 coverage の結果を解析し、低カバレッジファイルから順にテストを追加していく自動ループ。usage limit による中断に強い state file ベースの設計。

## 発火条件

以下のいずれかに該当する場合に proactively 使用:

- 「カバレッジを上げて」「テストを追加してカバー率を改善」
- 「coverage を N% まで climb」「coverage threshold を満たすまで」
- 「nightly で coverage を継続改善」（オートメーション化）

## 前提

- vitest v8 coverage が package level で動作する（`packages/core`, `packages/plugin-fs`, `packages/plugin-dialog`, `packages/schema`）
- `pnpm --filter <pkg> test --coverage` で JSON / lcov 出力できる
- `tests-coverage.yml` (CI) で 4 パッケージ matrix が走っている

## State File

`.claude/coverage-progress.json` を進捗管理に使用:

```json
{
  "target_line_coverage": 85,
  "packages": {
    "@rescript-tauri/core": {
      "baseline": 72.5,
      "current": 78.3,
      "files_completed": [
        "src/Window.res",
        "src/Webview.res"
      ],
      "files_skipped": [
        {
          "path": "src/Mocks.res",
          "reason": "test-only module, intentionally low coverage"
        }
      ],
      "last_updated": "2026-05-09T12:34:56Z"
    }
  },
  "iteration": 12,
  "max_iterations": 200
}
```

**重要**: `.claude/coverage-progress.json` は **gitignore する**（個人作業の進捗、commit 不要）。skill 起動時に `.gitignore` に追加されているか確認し、なければ追加。

## ループ手順

### Step 1: Baseline 取得

```bash
# 全パッケージの coverage を取得
for pkg in core plugin-fs plugin-dialog schema; do
  pnpm --filter "@rescript-tauri/$pkg" test --coverage --reporter=json > /tmp/cov-$pkg.json
done
```

state file が存在しない場合は新規作成、存在する場合は last_updated をベースに resume 判定。

### Step 2: Top 候補抽出

各パッケージの coverage report から、**line coverage が最低のファイル N 件**を抽出（既に `files_completed` / `files_skipped` に含まれるものは除外）。

```bash
# ranking 例（jq 使用）
jq -r '.coverageMap | to_entries | map({path: .key, lines: .value.s | length, covered: .value.s | with_entries(select(.value > 0)) | length}) | map({path, pct: (.covered/.lines * 100)}) | sort_by(.pct) | .[0:5]' /tmp/cov-core.json
```

### Step 3: テスト追加

最低カバレッジのファイル 1 件について:

1. 対象ファイル (`.res` / `.resi`) を Read
2. 既存テスト (`tests/runtime/*.test.mjs` など) を Read
3. **uncovered branch を狙うテストケース** を生成して `tests/` に追加
4. `pnpm --filter <pkg> test` で実行

### Step 4: 失敗時の Retry

テストが失敗したら **テストの方を修正**して再実行（最大 5 回）。5 回失敗したら `files_skipped` に reason 付きで記録してスキップ。

**禁止事項**:
- production code (`src/*.res` / `src/*.resi`) を変更してテストを通す
- assertion を緩めて pass させる（テストの意図が変わる場合は skip）

### Step 5: コミット

green になったら 1 ファイル分を 1 コミットに:

```
✅ Add test cases for <module> (coverage <before>% → <after>%)
```

### Step 6: State 更新と再開判定

state file を更新し、target threshold に到達するまで繰り返す:

```json
{
  "current": 79.2,
  "files_completed": ["src/Window.res", "src/Webview.res", "src/Path.res"],
  "iteration": 13
}
```

**中断対策**: 各 iteration の終わりに state file を fsync しておく。usage limit で中断しても次回セッションで `iteration: 13` から resume 可能。

### Step 7: PR 化

**main 直接 push 禁止**。10 commit ごとに PR を作成:

```bash
git push origin worktree-coverage-climb
gh pr create --title "✅ Coverage climb: round N (xx% → yy%)" \
  --body "Auto-generated by coverage-climber skill. See .claude/coverage-progress.json for state."
```

## ガードレール

| 項目 | ルール |
|---|---|
| Production code 変更 | **禁止**。`src/*.res` / `src/*.resi` には触れない |
| Test/build/generated 除外 | `tests/`, `lib/`, `*.res.mjs`, `*.test.mjs` は対象外 |
| Mocks 系除外 | `Mocks.res` は意図的に低カバレッジ。`files_skipped` に登録 |
| max_iterations | 既定 200。超えたら停止して人間レビュー |
| max_retries per file | 5 回失敗したら skip + reason 記録 |
| PR per N commits | 10 commit ごと（後続レビュー負荷を分散） |
| main 直接 push | 禁止。PR 経由のみ |

## 適用対象パッケージ

CI で coverage 計測している 4 パッケージ:

- `@rescript-tauri/core`
- `@rescript-tauri/plugin-fs`
- `@rescript-tauri/plugin-dialog`
- `@rescript-tauri/schema`

各パッケージごとに独立した state を持ち、独立した PR で進捗する。

## .gitignore への追加

skill 起動時に確認・追加:

```
# Coverage climber state file
.claude/coverage-progress.json
```

## なぜループ化するか

CC Insights レポート（2026-04 〜 2026-05）で:

- 「96 core tests を一括追加した後、続きの作業が usage limit で中断」
- `tests-coverage.yml` で 4 パッケージ matrix の coverage を計測しているが、観測フェーズで止まっており継続的な改善ループが無い

→ state file ベースで再開可能なループにすることで、usage limit を跨いでも進捗が保存され、長期的に threshold まで climb できる。
